# Orange Pi 4 Pro v0.1.0-beta.1

Accepted manual SPI/NVMe beta for the original **Orange Pi 4 Pro only**.
The runtime was built from `8f311c484d33aab2882472766bc6263d064004c8`.
Release source is the commit referenced by Git tag `v0.1.0-beta.1`; source-only
release documentation advances do not rebuild the accepted runtime.

## Behavior and acceptance

SPI → NVMe boot with SD removed is mandatory. The 2 GB SD is recovery media;
there are no routine SD writes. `manual-beta` keeps storage/accounts, admission,
ownership/locking, manual launch, stopped-disk checkpointing, backup/restore and
host update/recovery. Automatic dispatch is masked; complete automatic managed
lifecycle and automatic rollback remain deferred.

Final source-relevant CI passed 221 stages (3,011 executed, 817 declared CI
exclusions). Qualified native validation passed all 3,828 tests without skips.
One repaired A/B construction and independent full filesystem readback passed;
the original candidate was replaced only for an observed manual boot-lock defect.
The final root creates manual locks automatically and was physically cold-booted
and exercised through the documented unprivileged KVM service.

Three cold and three warm SPI/NVMe observations passed in total, reusing compatible
prior observations and including the repaired manual profile. Real KVM CPU/disk/
HTTP, guest-owned clean shutdown, checkpoint, restart and persistence passed;
compatible prior recovery/rollback/backup/restore evidence is retained. There was
no new soak or upstream conformance campaign. These modest checks are not a
statistical reliability claim or a guest OS compatibility matrix.

Physical deployment used the supported inactive-B update on existing STATE/GUESTS,
preserving normalized A and guest backups. The matching whole-NVMe image was
constructed and stream-verified; it was not destructively reinstalled during this
final run. Its BOOT matches the physically validated protected BOOT. See
[hardware acceptance](../evidence/manual-beta-hardware-acceptance-20261114.json).

## Distribution and limitations

Images remain private. The recovery SD includes the original unit's private SSH
host key. New NVMe STATE contains fresh machine/SSH identity and per-unit
management data; do not clone it to another unit. Other vendor redistribution
permissions remain unresolved. This release does not assert public binary or
blanket source redistribution clearance. Eligible public release notes/checksums
can accompany the GitHub prerelease without publishing these payloads.

Another identical Orange Pi 4 Pro needs its own identity and storage plan. No
other Orange Pi model or generic A733 board is supported. Keep recovery roots,
original/calibrated SPI snapshots and guest backups; use fresh target and idle
checks before writes. Vendor calibration can change SPI parameter metadata during
boot. Existing handled-interruption evidence does not prove recovery from every
power-loss or locked-kernel failure. See [known limits](../known-issues.md).
